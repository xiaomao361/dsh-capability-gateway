# 能力网关：清单与调用观察

## 1. 入口和职责

Host 入口 `index.js` 继续提供一个 `capability` 工具，新增 `inventory`、`history`、`stats` action。模型侧 inventory 返回当前 scope 的计数、根目录和有限异常摘要；history 返回最近 20 条记录，stats 返回当前 scope 的统计。完整能力清单仍由设置页 snapshot 返回。观察用 action 自身不计入业务调用统计。

Web/桌面设置页入口 `client.js` 通过 DSH 的原生客户端模块协议加载，注册「设置 → 内置插件 → 能力网关」标签页。页面分为接入清单和转发与统计两个视图，沿用 DSH 主题变量；不启动额外 HTTP 服务器。

Host 注册 `capabilityGateway/snapshot` 和 `capabilityGateway/review` 两个 Typert Remote。它们使用 DSH 现有的通信、身份认证、global resource 授权与生命周期。客户端在挂载 Remote 后声明 `remote.capabilityGateway` 注入；卸载时撤回 namespace、样式和设置页。Host 与 Client 描述均使用 strict codec，不能使用仅 Host 可接受的 src-json 参数描述。Zod 在 Remote 边界和方法边界校验输入，输出校验为 JSON；非法筛选不能降级成「全部」。

## 2. 接入清单的证据来源

页面按用户选择的**已存在活动 Agent**读取，不创建或唤醒会话。不选择时取登记顺序中的第一个活动 Agent；没有活动 Agent 时读取宿主范围，并明确提示不能确认会话预设的能力。

Skills 使用原生 `skills.snapshot` 的实际赢家，展示名称、说明、路径、来源、provider、模型/用户可调用策略，以及是否由网关接管。受管根目录单独扫描，分别展示读取状态；目录读取失败或原生发现不完整都不得显示为「没有技能」。被更高优先级同名能力覆盖、尚未进入该 scope 的条目单独标识。

保留 DSH 对 per-agent 文件系统 provider 的接入修复：网关 overlay 在 Agent scope 注册，rank 为 user-agents 的 499 / custom 的 299；数值较小优先。注册时排除受保护的全局赢家，以及同名但来自其他文件的全局能力，防止 scope 优先级覆盖用户、项目或未纳入的能力。不能用全局 overlay 的测试代替实际会话层级测试。

MCP 清单合并三个来源：

- 网关配置中的 `mcpServers`。
- 加载器可观察到的 `@deepseek-ai/dsh-mcp-client` 配置登记，仅提取 serverName、entryId、enabled、fiber phase。
- 当前 scope 的原生已注册工具 schema，按 MCP namespace 分组。

「已发现工具」只证明工具注册存在；不证明此刻上游可用。零工具可能由未加载、权限、断线或空服务造成，不直接判为离线。明确可观察的配置停用、插件启动失败另行显示。加载器不可用时标明配置覆盖不足；未挂载预设里的服务不保证可枚举。配置登记也不等同于本会话可见工具。

## 3. 记录与关联

`tools/pre-execute` 记录内存中的起点，`tools/execute` 观察实际转发目标，`tools/result` 取得**原生最终结果**。成功、错误和取消分别保存；pre-policy/guard 拒绝不会被算成成功转发。

网关 `search`、`load`、`describe`、`call` 留下操作记录。嵌套 MCP 调用归属同一个网关记录，不再计第二次。受管 MCP 与已识别受管 Skill 的原生直接调用单独记为 direct，用于观察是否绕过网关；其他原生工具不收集。

时间 `at` 为终态观察时间，页面按北京时间显示；文件名按 UTC 日期分组。网关记录保存单调时钟计算的耗时。没有观察到起点的直接调用可以没有耗时，不能伪造成 0。

同一 Agent 最近一次搜索与之后 10 分钟内的 load/call/describe 关联。保存展示给 Agent 的候选及采用排名：1 起表示候选中的位置，0 表示候选外，null 表示没有近期可关联搜索。跨 Agent 不关联；重载后不追溯猜测关联。显式指定或没有近期搜索的调用不能直接判错。

页面展开记录可查看：会话/调用/记录编号、候选、请求目标、实际转发目标、结果、错误类别和耗时。`review` 只允许将已有网关 load/call 标记为 `correct`、`wrong` 或 `unreviewed`，采用追加事件保存修改历史。模型工具没有自动打分入口。

## 4. 统计口径

统计来自最近 7 天、最多 10,000 条保留在内存中的操作/标记事件。可以按全部或指定活动 Agent 计算；结果/操作筛选仅筛选列表，不悄悄改变上方统计分母。

| 指标 | 定义与边界 |
|---|---|
| 网关 MCP 调用数 | route=gateway 且 action=call 的终态样本数，包含未转发的拒绝样本 |
| 调用成功率 | 成功 call / 实际转发（dispatched）的 call；参数校验和可用性拒绝不计入分母，仍计入调用数、错误数和记录列表；无转发样本返回 null |
| 搜索未命中 | not_found 或 matchCount=0 的 search 数；未提供查询词的列举（matchCount=null）不计为命中或未命中；发现异常不冒充未命中 |
| 候选内采用率 | candidateRank>0 的网关 load/call / 有 searchId 和 candidateRank 的网关 load/call；只关联确实返回过候选的搜索，无关联样本返回 null |
| 转发目标不一致 | 请求目标与原生 dispatch 阶段观察到的名称均存在且不同的 call 数 |
| 原生直接调用 | 受管能力以 direct 路径产生的操作数，和网关调用分开 |
| 人工标记 | 每个网关 load/call 最近一次有效标记；未评估不算正确 |
| p95Ms（API） | 有耗时的网关 call 样本，排序后 nearest-rank 95 分位；无样本 null |

调用成功不证明选对能力，候选内采用不证明语义正确，Skill 加载成功不证明工作流执行成功。目标一致性只能检查调度名称，不能证明 MCP 内部或远端数据正确。

记录从启用此版本开始；不补造旧版本历史。尚未终态或进程崩溃前未被观察到结果的调用可能没有记录，因此这是一组调用观察样本，不是完整业务审计。

## 5. 存储与失败保真

默认目录为 `$DSH_HOME/data/capability-gateway`，未设置 DSH_HOME 时为 `~/.dsh/data/capability-gateway`；`logDir` 可覆盖，测试必须使用临时目录。

按 UTC 日期追加 JSONL 文件，不重写或自动删除已有日志。目录创建权限 0700，日志文件 0600。重载从最近 8 个日文件读取后再按精确 7 天窗口裁剪；每文件最多读取尾部 8 MiB，总事件上限 10,000。截断、损坏行、读取失败和写入失败均显式标记样本不完整。

落盘串行排队，工具结果不等待磁盘写入。写日志失败不能把已经完成的 MCP 调用改为失败，否则可能引发重复执行。页面/API 显示存储异常；本进程任何已知写入失败计数保留，后一次写入成功不能抹除先前丢失落盘记录的证据。人工标记未落盘时必须报错。

## 6. 安全与隐私

日志使用字段白名单，只允许：随机记录号、会话/调用编号、终态时间、操作类型、能力种类/名称、路径类型、候选名称与排名、请求/转发名称、耗时、终态与错误类别、枚举形式的人工标记。

**不保存**搜索原文、用户请求、工具参数、返回正文、图片、完整错误正文、技能正文、MCP 地址、环境变量、请求头或凭据。查询内容也不做可反查的指纹记录。失败时保留类别和调用编号，进一步诊断使用原生 DSH 对应调用记录。

清单 API 只向有权调用此 Remote 的客户端投影必要元数据，绝不返回整份 Loader/MCP 配置。UI 用 React 文本节点渲染不可信描述，不拼接 HTML。没有清空、删除日志或修改接入配置的 UI。

## 7. 验证层级

自动检查使用本机安装包的真实 Cordis、ToolRuntime、SkillRegistry、FileSystemSkillProvider、TypertRegistry、TypertGateway；MCP 工具、技能目录、Peer 和存储故障采用隔离夹具。前端通过 React 静态渲染与组件交互测试检查筛选、页面切换、错误和人工标记。此外从安装包根 node_modules 加载真正的 Client Remote/Cordis，执行 apply/$mount、标签页注册、Host 往返、卸载和重载回归；只测试组件或 Host API 不足以证明客户端能启动。

原生 API 的 owner 调用与 non-owner 拒绝已验证。用户已确认 0.2.1 在真实 DSH 中恢复启动、两页可见且功能正常。0.2.3 清单布局的视觉/键盘体验、真实 MCP 调用及真实流量统计仍须应用内逐项验收；自动检查不证明这些已完成。PTC SDK 精简仍未实现，继续如实报告。


## 8. 自动发现与显式接管

自动发现只更新可观察的目录与工具，接管范围仍由 `skillRoots`、`mcpServers` 显式决定，不因安装了新第三方能力而自动扩大。

| 变更 | 当前行为 |
|---|---|
| 已配置且可监听的技能目录内新增或修改 Skill | 文件监听使扫描缓存和原生 Skill provider 缓存失效，下次原生发现/网关查询重新扫描。正常扫描缓存 2 秒；页面需手动刷新。 |
| 新增受管技能目录 | 加入 `skillRoots` 并重新加载插件。只扫描根目录直接子目录下的 `SKILL.md` 或根目录直接 `.md` 文件，不递归寻找任意深度的技能。 |
| 启动时不存在的受管目录后来被创建 | 按需扫描会重试；该目录启动时未建立监听，重新加载插件可建立监听，不能承诺已有原生缓存立即失效。 |
| 已接管 MCP 服务新增/移除工具 | 每次查询读取当前 Agent scope 的原生工具注册表，不另存工具清单；DSH 完成注册变化后随之更新。插件不主动轮询远端 `tools/list`。 |
| 在 DSH 新接入一个 MCP 服务 | 加载器配置/原生工具可观察后可进入清单；加入 `mcpServers` 并重新加载插件后才由网关接管。未纳入时保持原生暴露。 |

Skill 必须有可解析 frontmatter、有效名称与非空说明，并符合原生调用策略；`disable-model-invocation: true` 的用户专用技能不纳入模型网关，同名优先级与当前会话作用域仍生效。文件变化监听异常目前不会自动恢复监听；扫描的 2 秒缓存期限不等于完整的原生缓存恢复保证，必要时重新加载插件。

页面是一次读取的快照，没有后台自动刷新。刷新不会连接 MCP、探活上游或触发安装；观察到工具也不代表上游实时健康。

0.2.3 的接入清单使用分组可展开列表，删除表格最小宽度；名称与状态在摘要中，说明、来源、调用方式、路径和 provider 展开查看。长名称在摘要中省略，展开后完整展示；正文可换行。固定指标网格、记录筛选与折叠详情沿用 0.2.2。结果/操作筛选放在记录区，统计范围独立显示；错误/不完整提示不折叠，无样本比率保留 `—`。完整路径、编号、统计口径和隐私说明仍可展开读取。


## 9. 模型入口的上下文预算与调用校验（0.2.4）

`search` 支持 `kind=skill|mcp`，省略时搜索两类已接管能力。英文以单词边界匹配；长度 2 的命令必须是完整词，不让 `ve` 命中 `develop`、`improve`。较长英文词允许低权重前缀匹配。中文使用 `Intl.Segmenter` 分词，并去掉常见虚词；按名称、描述、查询覆盖度与词的区分度排序。混合语言查询中的显式英文标识提高权重；0.2.7 起还须通过第 12 节的零命中标识词、名称/关键词锚点和覆盖率检查，避免泛词掩盖目标标识。这是词法检索，不是语义模型或中英文翻译。

排序使用发现阶段保留的描述和 whenToUse；返回的 Skill/MCP 候选摘要统一最多 120 个 Unicode 字符（含省略号），描述换行合并。默认 5 条、最多 10 条，不返回完整 schema 或技能正文；需要时分别 describe/load。无匹配仍是可区分的 `not_found`，明确说明只搜索已接管第三方能力，原生、项目和未纳入能力走原方式，不能解释为整个 DSH 没有此能力。搜索失败不降级成未命中。指定 kind=mcp 时不依赖技能发现结果。

`call` 从当前 Agent scope 的同一份原生注册表读取参数 schema（与 describe 来源一致），在嵌套工具执行前校验。使用 Ajv 8.20.0、ajv-formats 3.0.1，支持 draft-07（默认）、2019-09 与 2020-12；固定依赖，Host 使用，客户端不加载 Ajv。校验不补默认值、不做类型转换、不删除字段，也不抓取远端 schema。按 schema 内容缓存最多 32 个校验器，schema 更新后重新编译。

必填、类型、嵌套字段、枚举、额外字段等违反 schema 时返回 `invalid_arguments`，错误文本包含相同 JSON Schema；不进入原生 MCP dispatch，不发远端请求。schema 无法编译、未知约束/格式或未解析引用时显式 `unavailable`，不会跳过校验继续调用。参数正确后继续经过原有 Agent、parent、rootCallId、signal、权限与 guard；上游执行失败仍为 `execution_failed`，不能伪装成参数错误。校验错误和 schema 不写入元数据日志，只保留类别和调用编号。

参考：[Ajv schema 版本与约束](https://ajv.js.org/json-schema.html)、[校验选项](https://ajv.js.org/options.html)。

模型侧 `inventory` 与 UI `snapshot` 分开：模型只返回 counts、skillRoots、覆盖完整性和异常摘要，省略逐技能说明和逐工具清单；默认最多 5 条异常，可用 limit 调整至 1–10，并返回异常总数、显示数和 truncated。kind=skill/mcp 只读取相应能力；根目录错误保持 count=null，完整性不足保持 complete=false，不以正常零值掩盖。这里 complete 表示所请求类别的发现覆盖，不代表上游健康或端到端可用。原生技能快照完整性与根目录读取分别保留，不能混为一个状态。

UI 继续取得完整 Skills、工具说明与原有元数据，并增加“能力类型”筛选。MCP registrations 在每个服务内按 entryId 去重；同一 entryId 出现矛盾状态时只保留一个登记，附 conflict/observations，失败观察不被健康观察覆盖，模型摘要显示 registration_conflict。清单仍不包含 Loader 的地址、环境变量、请求头或凭据。


## 10. 下游目录不可见时的入口路由（0.2.5）

模型搜索只能读取当前会话可见的工具名称、描述和已配置关键词，不自动知道聚合 MCP 下游有哪些服务。`acme` 等未收录的词若没有出现在这些字段中，不能声称已经发现该下游服务，也不能据此判定不存在。

直接排序无匹配且满足第 11 节短查询规则时，从当前会话可见且已接管的 MCP 工具中选择通用发现入口兜底：本地工具名包含独立的 search/find/discover/list 动词，优先搜索，再列举。只解析工具名，不按服务名分支；排除含 call/execute/create/update/delete/remove/write/patch/set 动词的工具，避免把调用或修改 endpoint 的工具当发现入口。server 名本身不参与入口判断。返回仍遵守 limit，摘要仍 ≤120 字。

兜底结果明确“无直接匹配”“可继续检索与路由”“不代表已找到目标能力或确认下游可用”，提示先 describe 返回的具体工具，再按 schema 将原查询交给入口。网关不自动调用、不抓下游列表、不探测真实上游；kind=skill 不走 MCP 兜底。没有可见入口时仍返回 not_found；技能发现失败、scope 权限、停用和未注册状态不能被兜底掩盖。

可配置 `mcpKeywords` 将服务关键词映射到该服务的可见发现入口。示例仅用于插件配置：

```yaml
mcpKeywords:
  acme-gateway: [acme, globex, initech]
```

这个配置提高相关入口的排序权重，搜索入口在同分时优先于列举入口；不让 call_endpoint 等执行器仅因服务关键词而入选，也不扩大 mcpServers 的接管范围。关键词命中仍标明“仅定位到 MCP 入口，尚未查询下游服务”。代码不含特定服务或下游别名。每服务最多 50 个非空字符串，每项最多 80 个 Unicode 字符；错误配置显式 invalid_config。

默认 `mcpKeywords: {}`。现有 profile 需通过 DSH 的插件管理能力显式更新配置后重载；修改 bundle 的 cordis.patch.yml 不等于已修改现有安装配置。0.2.5 通用兜底无需关键词即生效，示例关键词未自动写入用户 profile。

兜底时 matchCount 保留 0，candidates 保存实际展示的入口，搜索未命中统计继续计入该次无直接匹配；不能用入口数量伪装成直接命中。该操作成功返回可供继续检索的入口列表，并不代表能力匹配成功或下游可用。历史 UI 将这种记录显示为“无直接匹配 · N 个路由入口”，而不是“0 个候选”。关键词匹配的 matchCount 表示本地入口关键词匹配数，仍不能证明下游业务能力。

结果标签改为“技能”“MCP服务：服务名”或“MCP入口：服务名”；协议 action/kind 值保持原值。load 缺名称、未知技能、读取失败和空正文提示统一中文，保留 not_found/dependency_missing 类别及原生能力的使用指引。


## 11. 兜底仅用于短关键词（0.2.6）

0.2.5 的入口兜底会把不属于网关的长任务描述引向 MCP。0.2.6 将通用兜底限制为：规范化并去除首尾空白后不超过 24 个 Unicode 字符，且中文分词后有 1–2 个非虚词词项。两个条件必须同时满足。计数不去重，保留“拆”等单字实词；不能复用排序时忽略单字的词表，否则“Excel 拆 sheet”会误变成两个词。

无直接匹配的长句、超过 2 个词或超过 24 字的查询，返回 not_found，提示按原生方式使用能力、缩小为名称/短关键词，不返回 MCP 入口或建议调用的下一步。acme/globex 等短服务名仍可走通用兜底；kind、scope、未接管、失败和未注册边界不变。

这个限制只适用于“无直接匹配”的推测性兜底。工具名称、描述或显式 mcpKeywords 已命中的长查询继续返回已命中结果，不因查询较长而丢弃。短查询长度仍是词法启发式，不能视为已识别业务意图或证实下游能力。

被拦截的查询保持 matchCount=0、候选为空、not_found 错误，搜索未命中统计保留；短查询兜底仍保存实际展示入口，不将两者混为直接匹配。


## 12. 部分覆盖不能掩盖未知标识（0.2.7）

> 0.3.1 起本节的两条规则已被第 16 节替代：未知词不再一票否决，覆盖率分母改为目录收录词。保留本节作为当时的动机与回归背景。

0.2.6 对 `acme logs` 的 `logs` 部分命中一个日志类技能后直接返回，未知的 `acme` 被忽略，通用兜底未执行。0.2.7 在当前 scope、kind 筛选后的同一候选集合中统计每个查询词的命中文档数；词边界/前缀规则保持一致，名称、描述、whenToUse 和显式服务关键词均参与。

- 任一英文/数字关键词在该候选集合中零命中，整个查询视为没有直接匹配；不能用 logs 等通用词的命中绕过未知标识。
- 在候选名称或显式 mcpKeywords 中出现过的英文/数字词是已知标识锚点，每个返回候选都必须覆盖这些锚点。即使 `acme` 已由另一入口登记，那个日志类技能也不能只靠 `logs` 混入。
- 候选覆盖率至少 50%，边界 50% 保留。查询含英文/数字词时，覆盖分母使用这些词；其余中文上下文仍参与打分。纯中文查询的覆盖分母使用在当前索引中可检索的词，未收录的中文修饰语不一刀切否决，因此“查生产环境错误日志”仍能靠已收录的“日志”定位入口。
- 保留连续中文片段作为补充短语，避免 ICU 将“余额”切成两个单字后全部丢弃；“账单 余额”和“余额”单独查询均可命中。

没有合格候选后沿用 0.2.6 的短查询门槛：短服务关键词走明确标记的入口兜底；长任务描述保持 not_found、候选为空和原生能力使用指引。没有自动调用或 scope 放宽，搜索未命中统计仍按最终合格匹配数计算。

这是保守的词法检索门槛，校验覆盖不等于理解任务语义；不能据此承诺所有自然语言查询都不会误选。测试检查未知 acme/globex 与 logs 的组合、已配置关键词后的锚定、50% 边界与低覆盖、长句/短句分流、中文关键词，以及原有短命令与实例查询回归。搜索关联/日志隐私测试改为真实完整命中的查询，并仍验证原查询和工具参数不落盘，避免用误匹配作为成功关联的前提。


## 13. 页面层级与大数据量浏览（0.2.8）

两个设置视图继续使用 DSH 原生客户端模块，不增加服务器、路由或运行时依赖。视觉采用主题强调色、通栏分段导航、紧凑总览、主次指标与统一状态标签；不固定亮色背景，继续读取宿主主题变量。状态使用文字和标记共同表达，键盘焦点、原生 details、可聚焦列表滚动区、窄容器换行与 reduced-motion 保留。实际明暗主题、窄面板和键盘操作需在 DSH 中验收，React 测试不等于视觉验收。

接入清单按 MCP / Skills 分组，新增管理方式筛选，与名称/说明/来源、类型筛选组合。总览为当前快照全量计数，不随清单筛选改变；“网关管理”将服务与技能条目相加，不是工具数。每组默认 10 条，可选 20/50 条；工具明细每页 10 条。搜索先作用于完整清单及 MCP 工具说明，然后分页，不只搜索当前页。改筛选回到首页。两组清单滚动区最大高度 560px，工具明细也分页，避免一次渲染全部工具。发现不完整、根目录错误、MCP 启动失败及未观察到工具的数量不被分页隐藏；后者不判为离线。

统计视图先显示范围与存储异常，再展示两项主指标和四项辅助指标。调用记录是独立列表区，默认 10 条，可选 20/50 条，提供首页、上一页、下一页、末页和超过 5 页时的页码跳转。列表滚动区最大高度 510px，展开详情不继续撑长整个页面；分页位于列表区外，清空、末页和不足一页保留正确计数。分页及筛选不改变原统计口径、时间窗、保留上限和隐私字段。

### Remote 分页契约

`capabilityGateway/snapshot` 增加可选 `offset`（整数 0–10,000）、`anchorId`（非空字符串，最多 200 字符）；`limit` 的原范围 1–500 不变，UI 使用 10/20/50。Host / Client strict codecs 与方法边界同步校验。省略新增参数保持旧的最近记录行为；模型 history 默认最近 20 条不变。

`activity` 增加 `offset`、`limit`、`anchorId`，`total` 表示当前列表范围经筛选后的条数。先确定会话范围，再以 anchor 对应的操作事件限定列表上界，筛选后倒序切片。首次请求省略 anchor 时返回范围内最新操作事件 ID；之后翻页携带同一 ID，新增调用不会让页边界漂移或重复展示旧页。`stats` 始终基于整个所选会话范围内当前可读取的操作，不受 anchor、offset 或结果/操作筛选限制，因此翻页时新调用可以进入统计，但不会进入已锚定列表。列表说明提示刷新看最新记录。

切换记录范围、会话、结果、操作、页大小，以及点击刷新，均清除 anchor 并从首页重新读取。已翻页记录的人工标记刷新保留当前请求 anchor；标记不改变列表顺序或统计分母。offset 超出剩余记录时返回最后有效页；空范围返回 offset=0、anchorId=null。anchor 因七天裁剪、保留上限或会话范围变化不再存在时，显式报 `not_found: history anchor expired; refresh records`，不降级成正常空页。读取失败保留旧快照、显示错误并暂停分页，刷新可恢复；请求进行时明确提示正在显示旧快照，序号保护阻止旧响应覆盖新响应。

分页减少记录传输量与挂载行数；现有清单 snapshot 仍传输全量能力元数据，日志仍按原有上限在内存中计算统计，未引入数据库或持久分页缓存。每次请求和刷新不主动探测 MCP，也不写真实 profile。

### 视觉参考与证据边界

0.2.8 的布局参考来自一次内置 imagegen 生成的两页概念图（本机留存，未随仓库发布），非实际 DSH 截图，也未作为已获用户视觉认可的成品。实现保留其中的导航、总览、主次指标、状态标记、紧凑列表与独立分页结构。导航采用主题底色、强调色边框与底线，而非概念图的实心白字按钮；已从安装包欢迎页 CSS 读到宿主强调色的亮/暗模式取值，强调色不直接作为小字前景或白字背景，以免模式切换后对比度不足。真实渲染仍待人工检查。参考图中的“在线/离线”、同比变化、平均耗时、独立调用方及部分样例数值不具备本项目数据依据，不予实现；继续使用第 4 节已有指标及可观察状态。工具使用列表而非恢复被否定的四列表格；不增加历史趋势图。离线预览运行本次 client.js，使用明确标注的生成样例和模拟主题变量，不连接真实 DSH，不能证明真实主题、远程调用或视觉已验收。

## 14. 统计口径修正（0.2.9）

0.2.8 实机复测（真实 MCP 调用 + 本机会话）暴露三处读数问题，均为口径与文案，不涉及排序、兜底门槛、转发校验或权限：

- **调用成功率把拒绝算成失败**：`invalid_arguments` 与 `unavailable` 在网关侧就结束，从未进入上游工具；按全部 call 做分母会把参数手误读成 MCP 不可靠。现分母改为 `dispatched` 的 call，新增 `callDispatched`、`callRejected` 两个计数供界面说明，拒绝样本仍计入调用数、错误数与记录列表。
- **零候选搜索被当成“有关联搜索”**：关联链路用 `findIndex(...) + 1`，把“在候选中之外”和“这次搜索没有候选”都写成 rank 0。现在只有确实展示过候选的搜索才建立关联；搜索未命中之后的显式选择记为未关联，不进入候选采用率分母。
- **空查询冒充命中**：未提供查询词时按名称列出清单，头部曾写“匹配 N 项”，`matchCount` 也记为全量，搜索统计把它当命中。现改为独立文案“未提供查询词，按名称列出…”，`matchCount` 记 null，既不算命中也不算未命中，记录列表显示为“未提供查询词”。

回放边界：统计按存储的事件重算，新规则不会回溯改写已落盘的历史事件。旧记录里零候选搜索之后的调用仍带 rank 0，仍会出现在候选采用率分母；旧的空查询仍带旧的 `matchCount`。要得到干净口径，需等 7 天窗口把旧样本自然淘汰，或人工归档日志。这属于观察口径修正，不表示搜索语义正确性提升。

## 15. 版本标记与周报导出（0.3.0）

迭代闭环的前提是“改完之后数字能和改之前分开”。0.3.0 只做这件事，不引入服务端、不上送数据：

- **版本标记**：operation 事件新增 `plugin` 字段，写入时用运行进程的打包版本盖章（读包内 `package.json` 的 `version`，读取失败记 null，不让插件启动失败）。读盘时保留落盘值，因此 0.3.0 之前的事件没有该字段，周报里显示“未记录（0.3.0 之前）”，不会被追认成新版本。review 事件不参与按版本统计。
- **周报来源**：`EventJournal#summary()` 与 `snapshot()` 共用 `computeStats`，所以两边分母一致；另外按版本分组重算一遍，并给出错误码、调用目标、技能加载、兜底次数、未命中率与兜底率。`report.js` 只负责把 summary 渲染成 Markdown / JSON，自身不读事件、不读参数、不读查询原文。
- **两个出口**：模型侧 `capability action=report` 返回 Markdown；设置页「导出周报 / 导出 JSON」经 strict Remote `capabilityGateway/report` 取 `{ filename, content }` 后由浏览器写盘。两条路径共用同一份 summary，口径不会分叉。
- **边界**：周报只是单机观察样本，不含查询原文、工具参数、结果正文、错误正文、凭据或日志目录路径；不自动上送，是否转交由用户决定；空窗口用 — 表示缺失而不是 0；样本少于 20 条时明确提示不构成趋势；文件名使用北京时间日期，便于按周归档。

“导出”不等于“已验收成功”：调用成功率只说明上游是否稳定，候选内采用率不判断语义正确性，按版本对比也只在样本足够时才成立。

## 16. 检索召回修正（0.3.1）

0.2.7 的保护性规则在真实中文任务上误杀严重：同一批 9 条请求，平铺目录能选对 8 条，网关只选对 1 条。0.3.1 调整词法规则并引入技能别名，不改变转发、权限和统计口径。

### 改了什么

- **通用词不再当作信号**：`log(s)`、`error(s)`、`data`、`tool(s)`、`service(s)`、`file(s)`、`page`、`code` 等任务通用词，以及 `当前`、`现在`、`今天` 等中文副词，从查询与索引两侧移除。这样 `acme logs` 只剩 `{acme}` 仍会失败，而 `服务` 不再是一个有效锚点。
- **未知词不再一票否决**：原先任一英文词零命中就整条查询返回空，`spacing grid layout looks off`、`device reboots with black screen` 因此全部 miss。现在未知词只稀释得分；是否返回由“命中数 ≥ 2（多词查询）或命中唯一已知词”决定。
- **覆盖率改用已知词**：分母从“查询的全部词”改成“本目录确实收录的词”，避免长句被未收录的修饰语拖死。
- **中文 n-gram 补齐**：ICU 会把 `看门狗复位` 切成单字，导致整个词永远搜不到。现在对连续汉字补充 2–4 字 n-gram，只保留目录里真实出现的组合；统计覆盖时把互相包含的命中折叠成一次（`并核对`/`并核`/`核对` 只算一次）。
- **词形回退**：`reboots`/`errors`/`logs` 会回退到 `reboot`/`error`/`log`，只对 ≥4 字母的英文生效，`ve`、`ecs`、`sdk` 这类短标识不受影响。
- **技能别名**：`SKILL.md` 可写 `keywords:`（数组或逗号分隔），也可用 `skillKeywords` 配置覆盖；本机另有一份 `local/skill-keywords.json` 本地别名包（不进发布包，`local/` 已忽略）。别名命中按 12 分权重计入，并在长查询里视为显式锚点。

### 证据与边界

`tests/retrieval.test.js` 固定 25 条中英任务（快照目录 = 一次本机安装的被接管能力 + 别名）：

| 条件 | hit@1 | hit@5 |
|---|---|---|
| 同一批 9 条（0.2.7 规则，实测网关） | 1/9 | 3/9 |
| 同一批 9 条（0.3.1） | 8/9 | 9/9 |
| 25 条（0.3.1） | 22/25 | 25/25 |

负例保持干净：`acme logs`、`globex logs`、`把这份 Excel 拆成多个 sheet 并核对公式`、`查一下明天杭州的天气` 都不返回直接匹配。

这是词法检索，不是语义模型：别名是主要的中英桥梁，没有别名时中文依旧搜不到英文描述；同一族里的多个候选仍可能把 CLI 排在文档检索前面。多词查询要求命中两个词，比原来的 50% 覆盖率更严，可能漏掉只提到一个方面的查询；这是用召回换“单个意外词不能决定结果”的取舍，由上面的固定集持续度量。

### 复核方式

```sh
node --test tests/retrieval.test.js
```

命中率变化必须同时看负例；只提高 hit@1 而让 `acme logs` 复活，等于把 0.2.7 修好的问题又放回去。

## 17. 分层暴露（未实现）

当检索召回仍低于原生语义匹配时，让“常用能力保持原生可见、长尾进入网关”是唯一不牺牲准确率的收敛方式。0.3.1 未实现，排序仍按目录顺序，不做使用频率统计。

## 18. 未知安装与未知下游（开源边界）

这个插件发布给别人用，无法预设对方的 MCP 是平铺的一堆工具、还是像聚合网关那样只暴露 `list_tools`/`call_tool`，也无法预设对方说的语言。0.3.1 的别名包是本机数据，但“下游目录快照”是按某个具体聚合网关的形状想出来的，**不作为默认设计**。

插件只依赖三件可观察的事：

1. 当前 scope 里已注册工具的名称与描述；
2. 被接管技能 `SKILL.md` 的 frontmatter；
3. 本机调用日志（只有元数据）。

### 三种下游形态

| 形态 | 特征 | 网关的处理 | 依赖 |
|---|---|---|---|
| 平铺 | 每个工具就是一个真实能力 | 直接索引，命中后 describe → call | 无 |
| 聚合 | 只暴露 `search_tools`/`list_tools`/`call_tool` 之类入口，真实能力在下游 | 按名称里的发现动词识别入口，miss 时把入口交给模型委托一次；**不解析下游返回结构、不缓存目录、不推断可用性** | 无（通用规则） |
| 极薄 | 只有一两个工具、描述很短 | 命中就返回，miss 就 not_found 并提示原生路径 | 用户配置关键词 |

第二条是 0.2.5 就有的通用兜底，不含任何服务分支；聚合方叫什么都无所谓。想让它命中得更准，只能靠数据：`mcpKeywords`。

### 域知识只能是数据

- 技能作者随包带：`SKILL.md` 的 `keywords:`（跨安装可移植）。
- 本机：`local/skill-keywords.json`（不进发布包）。
- 团队/安装：`skillKeywords`、`mcpKeywords` 配置。

默认全部为空。开源之后，“中文能搜到英文技能”不是插件能力，而是这几处数据的覆盖度；没有数据就搜不到，这是诚实的行为，不是缺陷掩盖。

### 发布规则（可执行）

- 发布代码里不得出现具体服务名、厂商名或技能名 —— `tests/portability.test.js` 扫描 `index.js`、`search.js`、`client.js` 等，注释除外。
- `package.json` 的 `files` 不含 `local/`、`work/`、测试与文档；`tests/portability.test.js` 固定校验。
- 默认配置保持中性：包内 `cordis.patch.yml` 的 `skillRoots` 与 `mcpServers` 为空，接管范围由使用者的 profile patch 提供（0.3.2 起）。id 补丁整体替换 `config`，覆盖时要把需要的键写全。
- 周报只在用户主动导出时产生，不含原文，也不自动上送。

### 撤销的设想

“一次性读取下游目录并缓存成候选”依赖对方返回可解析的结构，且把“目录里有”误当成“可用”，对平铺 MCP 又没有意义。它只适合特定聚合器，不适合作为通用特性；0.3.2 只保留“发现入口委托 + 关键词包 + 本机使用频率分层”这三件通用的事。

## 19. 名称索引与别名包（0.4.0）

隐藏目录省了上下文，代价是模型**不知道自己不知道什么**：搜不到就以为没有。0.4.0 补两件事，都不改变“细节按需取”的前提。

### 名称索引（`promptIndex`，默认开）

系统提示里附一段有界的能力名单：技能名与 `mcp__<server>__*` 工具名，逗号分隔，按 `promptIndexChars`（默认 2000，上限 6000）截断，超出以 `…+N more` 结尾。名单只含名字，不含描述、schema 或参数。

- 作用：模型看到 `release-notes` 这样的名字，可以直接 `load`，不必先用词法搜索赌一次；这也让“能力很多时知道有哪些”不再依赖检索命中。
- 成本：约 2k 字符，对比完整目录（本例 11.7k 字符）仍是数量级差别，且随能力数量增长到上限就停。
- 边界：名单来自当前 scope 的注册表与技能根目录，不是全库；`promptIndex: false` 可关闭，`promptIndexChars` 可调。名字不等于可用：加载失败仍走原有错误。
- 实现注意：名单快照独立于技能扫描缓存（`indexNames`），否则启动时的空扫描会污染 provider 缓存两秒，导致刚装的技能“看不见”。

### 别名包（`keywordPacks`）

`keywordPacks` 是文件路径数组，每个文件是 `{ "<name>": ["关键词", ...] }`。多个包与 `local/skill-keywords.json`、`skillKeywords` 配置**叠加**而不是覆盖：同一个技能的别名取并集。缺失、损坏或不可读的包直接跳过，不阻塞启动。

这样“中文能搜到英文技能”可以变成可分享的数据：社区为公共技能维护一份别名包，使用者按顺序加载多份，插件本身不带任何具体技能名（`tests/portability.test.js` 保证）。

### 检索集的位置

`tests/retrieval.test.js` 用一份**合成目录**跑 CI（通用名字，不含任何真实技能）；本机的真实快照放在 `local/retrieval.json`（gitignored、不进包），存在时用同一套阈值一起跑，不存在时该用例跳过。开源仓库因此不带某个人的技能清单。
